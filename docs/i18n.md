# Translations (i18n)

The adapter is published with the ioBroker standard set of **11 languages**:

`en` (base and fallback), `de`, `ru`, `pt`, `nl`, `fr`, `it`, `es`, `pl`, `uk`, `zh-cn`

## Where the texts live

| Component                     | Files                                                                          | Notes                                                                               |
| ----------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| Adapter admin UI (jsonConfig) | `admin/i18n/<lang>.json`                                                       | managed with `translate-adapter`; `admin/words.js` is deprecated and must not be edited |
| ioBroker metadata             | `io-package.json` → `common.titleLang`, `common.desc`, `common.news.<version>` | must contain all 11 languages; kept in sync by `translate-adapter`                  |
| Web app (PWA)                 | `src-pwa/src/i18n/<lang>.json`                                                 | `i18next`/`react-i18next`; own key set (UI texts), `en.json` is the base            |
| Reports (PDF/XLS)             | generated at runtime                                                           | language from the user setting, instance language as fallback                       |

Deliberately **not** translated: API error responses (they carry stable error codes, the client
translates them) and ioBroker state names (`common.name` is English + German, per ioBroker convention).

## Workflow

1. Add new text **only** to the English base file (`admin/i18n/en.json` or `pwa/src/i18n/en.json`).
2. Run the translation tool from the adapter folder:

    ```bash
    npm run translate                 # all languages
    npm run translate -- -l de ru     # only selected languages
    npm run translate --rebuild       # rebuild every file from scratch (do not mix with manual fixes)
    ```

    Set `DEEPL_API_KEY` for higher quality (DeepL is preferred, otherwise Google Translate is used).

3. Review the generated diff – machine translation is a draft, not a final result.
4. Run the completeness check — same keys as `en`, no text left in the English original, no text used in the
   code without a key, metadata complete:

    ```bash
    npm run check:i18n
    ```

5. Commit the language files together with the code change that introduced the text.

## Rules

- Never rename or repurpose an existing key; remove keys only with `translate-adapter`
  (`remove-key`, `remove-translations`).
- No hardcoded visible text in code or JSON configuration.
- Use placeholders and ICU formatting instead of string concatenation for sentences.
- Format dates, numbers, currencies and units with `Intl` – never assemble them manually.
- Report texts and time zones follow the user's settings, never the server environment.
- PDF exports need embedded Unicode fonts that cover Cyrillic and CJK (`ru`, `uk`, `zh-cn`).

## Review status

The web app texts were translated once with `translate-adapter` (Google, without a DeepL key) and the core
terms were corrected by hand: “punch” means clock-in/out in this app, but a machine reads it as a fist punch,
and “PIN” came back as the sewing pin. Corrected for all nine languages: `nav.dashboard`, `punch.*`
(now, quick, in, out, open, closed, sent, last, worked, target, balance), `month.open` and the `admin.user.pin*`
keys. Everything else is machine translation and is an acceptable draft — please update the table when you
review a language.

**Status of the web app (`src-pwa/src/i18n/`):** `en.json` and `de.json` are maintained by hand. The other
nine files contain real translations (same key set, so `npm run check:i18n` passes) and are machine translated
apart from the corrections above. The check also fails when a value is still the English original; terms that
are identical in every language on purpose are listed in `$AllowedIdentical` in `tools/check-i18n.ps1`. Last
pass (2026-09): three leftovers were translated by hand — `month.balance` (`es`), `absences.portion` (`uk`),
`terminal.title` (`it`) — and a check for text keys that the code uses but `en.json` lacks was added.
Regenerate or refine them with:

```bash
DEEPL_API_KEY=… npx translate-adapter translate -b src-pwa/src/i18n/en.json -a src-pwa/src/i18n -l ru
```

The translator only fills **missing** texts: delete or empty a language file to have it translated again.
